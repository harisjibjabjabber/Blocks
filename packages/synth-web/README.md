# Standalone browser instrument

This independent instrument loads the portable core as raw WebAssembly in an AudioWorklet. It imports no Blocks application code or UI framework. The integrated ABI4 surface has two oscillator waveform/level controls, waveform feedback, a tone canvas with filter mix, separate curved Amp/Filter envelopes, Character/Motion/Fullness, Sauce (Drive/Pitch Drop), a top-right Volume/peak control, a playable keyboard and collapsed Precision. The new surface awaits independent UI approval; physical-phone and listening acceptance remain separate gates. This is a prototype, not a shipped VST or a replacement for Blocks production audio.

Install/activate official Emscripten 7.0.0 and set `EMSDK` to its directory. With Node 22 and Python available:

```sh
node scripts/build-synth.mjs
python -m http.server 41821 --bind 127.0.0.1 --directory packages/synth-web/build
```

Open http://127.0.0.1:41821 and press Start sound. Serve the entire output folder, including fonts and their license notices, to host it independently; deployment requires HTTPS (localhost is allowed). No backend is needed. MIDI is optional and requested only through Connect MIDI; browser/device support varies. The font files are existing handover assets with OFL notices; synthesis needs no sound assets.

Touch/glissando keys, desktop ASDF keyboard input, a real output waveform, descriptor-based parameters, Init, versioned JSON patch import/export, Stop and optional MIDI are supported. Edit a patch before enabling sound. Amp/Filter ADSR, Pitch Drop and settling settings snapshot on note-on; cutoff, filter amount/mix, Drive and drift amount/speed affect held notes through the core's smoothing. The reference keyboard uses channel 15; external MIDI preserves its channel. Hiding the page stops sound, losing focus releases notes, and leaving closes the audio context.

The latest authorized host contract separates Character recipe 5 (Drive parameter 12 only) from Motion recipe 3 (drift depth 13, attack settling 32, settling time 33 and velocity movement 34). Character must not alter pitch or drift speed. Motion's first 60% reaches 4.8 cents drift and 1.2 cents settling, then 40/12 at 85% and experimental maxima 120/60 at 100%. Its macro leaves Drive and speed 14 unchanged, uses a 180ms settling time and maps velocity sensitivity up to .85. The user requested an upper end capable of sounding excessive to find their own sweet spot; these are calibration limits, not recommendations. Motion details expose Speed, Attack settling, Settle time and Velocity. Editing owned targets 32/33/34 away from the recipe shows Custom; independent Speed changes do not mark the depth macro Custom, and need no extra customization flag. The three primary controls remain Character/Motion/Fullness. Presets preserve the preceding version-4 physical sound by explicitly seeding Motion and speed separately, not by coupling the live Character dial. The scoped phone/desktop interaction review passed, including keeping the keyboard playable with Motion details open.

Advanced core settling spans0–80 cents and drift0–120 cents; there is no combined drift-plus-settling clamp. Widening ranges does not change old physical values or fix the pitch mechanism. Patches preserve actual physical values. The rounded [user movement reference](../../docs/audio-references/user-movement-20ct.json) records an accepted20-cent/.58-Hz/4.8-cent-detune example, not a hard cap or blanket approval of Drive/Fullness sound.

Configured movement maxima are bounds, not guaranteed excursions: random per-note targets, velocity scaling, slow drift buildup and the short settling decay all affect the result. Touch-key attack velocity comes from vertical strike position, not finger pressure; computer-keyboard input uses .75 and MIDI uses the incoming velocity. The current glissando path uses .75 for the newly entered key. The separate `scripts/probe-synth-pitch.mjs` diagnostic measures actual Sine output frequency for old40/8 and expanded120/60 physical settings, preserving exact source/parameter manifests. It confirms note-dependent and velocity-dependent excursions; it does not establish which setting sounds musical.

Factory patches are Velvet Current, Glass Garden and Low Tide. Preset/import/Init release voices; normal gestures do not. One completed pointer gesture creates one Undo entry. Escape/pointer cancellation restores the exact patch, and another editing pointer cannot steal the gesture; keyboard pointers remain independent. Each oscillator offers Sine, Triangle, Saw, Pulse and Square. Square fixes duty at 50%; Pulse alone follows pulse width. Independent levels can mute either oscillator without changing the other. Waveform selection changes live through a short core crossfade; no notes are rewritten. ABI/patch 4 stores 35 values. Imports of v1/v2 retain Saw/Pulse defaults; v1 gains Fullness zero. All v1–v3 patches derive independent levels from their saved Mix and receive neutral filter-envelope/movement additions. The Fullness sound itself has intentionally changed to correct the previous detuned-note cancellation.

The filter ADSR is per voice, separate from amplitude, with bipolar amount in semitones around the base cutoff and an independent dry/wet mix. Its release does not extend a voice beyond the amplitude envelope. Per-note pitch settling uses a separate seeded random stream, returns toward the played pitch and scales with velocity sensitivity; it does not automate or rewrite MIDI. At their zero defaults, the new movement controls preserve the previous drift sequence. The scoped automated phone/desktop interaction review passed; physical-phone and musical listening acceptance remain outstanding.

The current standalone instrument adds inline oscillator level dials, an independent Mono toggle and separate Off/Arp/Strum modes. Its core performance configuration is separate from the unchanged 35-parameter tone patch; the scoped phone/desktop review and 31 actual-browser checks passed. Mono uses last physically held priority, then pedal-latched fallback, with channel/key repeat counts. Switching mode or Mono panics and clears held/generated state: release and press keys again. Arp anchors normalized exponential Curl to exact four-beat spans, uses BPM 40–240 and Curl ±.8, and deliberately resets the rate at each bar seam. Parameter changes while running wait for the next bar; adding notes does not reset phase. Strum collects a chord for 20ms, then spreads it once over 0–100ms; zero spread is immediate. Releasing a note before its scheduled attack cancels it even under pedal. Order/random flutter are bounded and seeded; there is no combined Arp+Strum or random-octave mode in this slice. Physical-phone latency/CPU, the musical Curl seam, Strum collection latency and sound quality still require listening/device acceptance.

Envelope timing gestures are relative to the full plot width, with Shift providing finer desktop movement. Points and Precision dedicate 70% of timing travel to 30 ms–2 s; short and long tails remain available up to the unchanged core limits. The graph uses one linear elapsed-time axis, so a 1ms attack stays at the left edge. Its illustrative key-up follows a short hold; it is not a fixed note length. The scale freezes during a gesture and fits again on release; 44px stage readouts remain editable when points coincide. Labels show physical times. Curves use the core's `progress^(2^bend)` law; decay's vertical position sets sustain. These are UI editing maps, not changes to saved seconds or the core's automation mapping.

The visible waveform is labelled Preview when it shows ideal selected oscillator shapes, and Output (auto) when it shows actual analyser data. Display-only scaling keeps quiet playing visible and never changes the sound or acts as a level meter. Top-right Volume controls the existing output-gain parameter. Its peak indicator uses actual stereo maxima accumulated across every audio block: amber is near full scale, red is finite output at/above 1 or an invalid-sample warning. Peaks hold until Clear peak. Intentional Drive saturation does not itself trigger digital clipping. No end-to-end forced clipping claim is made; unit tests check threshold/channel/interval handling using known samples.

Fullness now adds a small same-phase antialiased harmonic residual before the shared Tone/Drive path, preserving the original oscillator foundation. It no longer replaces the signal with a dark four-pole filter. It is not a Moog circuit model, and its musical character still needs listening acceptance. The broader drive/ladder study, internal noise texture, resonance, unison, recorded/drawn movement and effects suite remain future work. That includes the user's OTT-style multiband compression idea; no such processor is implemented by Character or Drive.

The adapter reserves 16 MiB of WASM memory, a 1024-event queue and buffers for audio blocks up to 2048 frames. Oversized blocks produce silence; queue overflow panics. The C++ render path allocates no heap memory, but JS messaging/telemetry is not allocation-free. Real mobile CPU, thermal, latency and hardware MIDI validation remain release gates.

The browser proof needs the server above and Chrome (`CHROME` can select its executable). It runs in a separate temporary profile, measures actual analyser output, checks held-note filter/Fullness changes and stopping/resume, and captures 320/390/1440 px layouts. It also exercises gestures, Undo, pointer cancellation/ownership and versioned file import/export. Automated signal checks do not establish musical sound quality or physical phone usability.

The current integration passes 19 core groups (12 tone and 7 performance), 23 Node tests and 31 actual-browser checks, plus an independent scoped phone/desktop UX review. Five exact-manifest audition WAVs and 45 benchmark configurations cover the updated core. These results do not establish physical-phone or musical listening acceptance. The independent Drive diagnostic rendered 130 actual-core cases with exact patch/event/source-hash manifests and two fixed-gain comparison WAVs. It found significant detune-related energy movement and DC with asymmetric Pulse. Controlled AC energy increased monotonically through Drive 1/2/4/8/12; this neither invalidates perceived middle-Drive thinness nor proves a Drive-induced phase shift. The recordings are material for listening, not evidence that listening approval has occurred.
