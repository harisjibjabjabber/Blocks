# Standalone browser instrument

This independent instrument loads the portable core as raw WebAssembly in an AudioWorklet. It imports no Blocks application code or UI framework. The current ABI5 integration has two oscillator waveform/level controls, waveform feedback, a tone canvas with filter mix, separate curved Amp/Filter envelopes, Character/Motion/Fullness, ordered Sauce audio blocks, a top-right Volume/peak control, a playable keyboard and collapsed Precision. New changes require their scoped UI review; physical-phone and listening acceptance remain separate gates. This is a prototype, not a shipped VST or a replacement for Blocks production audio.

Install/activate official Emscripten 7.0.0 and set `EMSDK` to its directory. With Node 22 and Python available:

```sh
node scripts/build-synth.mjs
python -m http.server 41821 --bind 127.0.0.1 --directory packages/synth-web/build
```

Open http://127.0.0.1:41821 and press Start sound. Serve the entire output folder, including fonts and their license notices, to host it independently; deployment requires HTTPS (localhost is allowed). No backend is needed. MIDI is optional and requested only through Connect MIDI; browser/device support varies. The font files are existing handover assets with OFL notices; synthesis needs no sound assets.

Touch/glissando keys, desktop ASDF keyboard input, a real output waveform, descriptor-based parameters, Init, versioned JSON patch import/export, Stop and optional MIDI are supported. Edit a patch before enabling sound. Amp/Filter ADSR, Pitch Drop and settling settings snapshot on note-on; cutoff, filter amount/mix, Drive and drift amount/speed affect held notes through the core's smoothing. The reference keyboard uses channel 15; external MIDI preserves its channel. Hiding the page stops sound, losing focus releases notes, and leaving closes the audio context.

Character recipe5 controls Drive12 only. Motion recipe4 owns drift depth13, settling32/time33, velocity movement34 and Envelope response35 fixed to1; neither macro changes independent Speed14. Motion reaches4.8/1.2 cents drift/settling at60%,40/12 at85% and experimental maxima120/60 at100%, with180ms settling and up to.85 velocity sensitivity. Those maxima are user-requested calibration territory, not musical recommendations. Motion details expose Speed, Attack settling, Settle time and Velocity. Owned values outside the recipe show Custom, including advanced response0; independent Speed changes do not. Character/Motion/Fullness remain primary. Presets seed physical Motion/speed values separately; new processing is not claimed to preserve older nonzero Fullness audio. The scoped phone/desktop review passes, including a playable keyboard with Motion details open.

Advanced core settling spans0–80 cents and drift0–120 cents; there is no combined drift-plus-settling clamp. Widening ranges does not change old physical values or fix the pitch mechanism. Patches preserve actual physical values. The rounded [user movement reference](../../docs/audio-references/user-movement-20ct.json) records an accepted20-cent/.58-Hz/4.8-cent-detune example, not a hard cap or blanket approval of Drive/Fullness sound.

Configured movement maxima are bounds, not guaranteed excursions: random per-note targets, velocity scaling, slow drift buildup and the short settling decay all affect the result. Touch-key attack velocity comes from vertical strike position, not finger pressure; computer-keyboard input uses .75 and MIDI uses the incoming velocity. The current glissando path uses .75 for the newly entered key. The separate `scripts/probe-synth-pitch.mjs` diagnostic measures actual Sine output frequency for old40/8 and expanded120/60 physical settings, preserving exact source/parameter manifests. It confirms note-dependent and velocity-dependent excursions; it does not establish which setting sounds musical.

Factory patches are Velvet Current, Glass Garden and Low Tide. Preset/import/Init release voices; normal gestures do not. One completed pointer gesture creates one Undo entry. Escape/pointer cancellation restores the exact patch, and another editing pointer cannot steal the gesture; keyboard pointers remain independent. Each oscillator offers Sine, Triangle, Saw, Pulse and Square. Square fixes duty at 50%; Pulse alone follows pulse width. Independent levels can mute either oscillator without changing the other. Waveform selection changes live through a short core crossfade; no notes are rewritten. ABI/patch5 stores40 values, adding Envelope response35, Drive enabled36, Pitch Drop enabled37, Audio order38 and Fullness enabled39 to the existing35 parameters. New patches enable envelope response; v1–v4 migration sets response0 for manual compatibility, enables the components and selects default order. Imports of v1/v2 retain Saw/Pulse defaults; v1 gains Fullness zero. All v1–v3 patches derive independent levels from saved Mix and receive neutral filter-envelope/movement additions. Fullness at nonzero values intentionally changes sound; preservation of recipe physical settings is not a promise of unchanged audio through that new DSP.

Envelope response uses curved amplitude attack/decay/sustain/release shape to restrain long-note movement while allowing more short-lived attack character. It is continuous, snapshots per note, never exceeds configured movement amounts, and uses the user's29.8-cent drift/8.9-cent settling examples as starting budgets. Zero Sustain with a long Decay is not treated as an immediate pluck. Advanced response0 bypasses this adaptation without altering stored Motion values. Core analytic/behaviour checks and actual-output pitch regressions are distinct from listening acceptance.

The filter ADSR is per voice, separate from amplitude, with bipolar amount in semitones around the base cutoff and an independent dry/wet mix. Its release does not extend a voice beyond the amplitude envelope. Per-note pitch settling uses a separate seeded random stream, returns toward the played pitch and scales with velocity sensitivity; it does not automate or rewrite MIDI. At their zero defaults, the new movement controls preserve the previous drift sequence. The scoped automated phone/desktop interaction review passed; physical-phone and musical listening acceptance remain outstanding.

The instrument has round inline oscillator level dials, independent Mono and separate Off/Arp/Strum modes. Performance configuration is separate from the40-parameter ABI5 tone patch. Mono prioritizes physically held notes, then pedal-latched notes, with channel/key repeat counts. Switching mode/Mono panics and clears held/generated state: release and press again. Arp uses exact four-beat spans, BPM40–240, Curl±.8, straight divisions through64th and triplets through16th. The deliberate bar-seam rate reset remains. Chord changes restart immediately, with subsequent changes grouped inside a fixed non-sliding20ms window to avoid repeated restart attacks; same-sample inputs form one chord. Timing edits wait for the next bar unless a chord restart applies them first. Strum collects for20ms and spreads once over0–100ms; zero spread is immediate. Release cancels pending attacks even under pedal. There is no combined Arp+Strum or random-octave mode. Current31 core groups,24 Node tests,32 browser checks and independent scoped UX pass; physical-phone and musical acceptance remain separate.

Envelope timing gestures are relative to the full plot width, with Shift providing finer desktop movement. Points and Precision dedicate 70% of timing travel to 30 ms–2 s; short and long tails remain available up to the unchanged core limits. The graph uses one linear elapsed-time axis, so a 1ms attack stays at the left edge. Its illustrative key-up follows a short hold; it is not a fixed note length. The scale freezes during a gesture and fits again on release; 44px stage readouts remain editable when points coincide. Labels show physical times. Curves use the core's `progress^(2^bend)` law; decay's vertical position sets sustain. These are UI editing maps, not changes to saved seconds or the core's automation mapping.

The visible waveform is labelled Preview when it shows ideal selected oscillator shapes, and Output (auto) when it shows actual analyser data. Display-only scaling keeps quiet playing visible and never changes the sound or acts as a level meter. Top-right Volume controls the existing output-gain parameter. Its peak indicator uses actual stereo maxima accumulated across every audio block: amber is near full scale, red is finite output at/above 1 or an invalid-sample warning. Peaks hold until Clear peak. Intentional Drive saturation does not itself trigger digital clipping. No end-to-end forced clipping claim is made; unit tests check threshold/channel/interval handling using known samples.

Fullness now adds stronger antialiased harmonic colour and DC-free low-band body to the dry foundation. Its whole stage follows Drive by default; reversing the order allows Drive to compress that body. Both paths stay warm and order changes crossfade. The body is a positive additive difference between approximately180Hz and10Hz one-pole states, not a dark-filter replacement or broadband output-gain control. Fixed-gain tests at Drive12 show about+4.8dB low-band versus+1.8dB high-band change for detuned bass; overall level can rise. Fullness0 fingerprints match the earlier dry output across the comparison fixtures. It is not a Moog circuit model, and its stronger character still needs listening acceptance. The broader drive/ladder study, texture, resonance, unison, stereo Space, recorded/drawn movement and effects catalogue remain future work; no inactive module buttons or third-party equivalence claims are implied.

The current Sauce rack processes generic mono audio per voice after Tone and before pan. Drive/Fullness are real ordered audio stages; Pitch Drop remains a note-pitch tool with its own enable state. A future stereo Space processor must operate on a two-channel bus after voice panning/summing, not merely rename this mono rack. See the [product plan](../../docs/synth-product-plan.md) for the deferred effects/voicing catalogue.

The adapter reserves 16 MiB of WASM memory, a 1024-event queue and buffers for audio blocks up to 2048 frames. Oversized blocks produce silence; queue overflow panics. The C++ render path allocates no heap memory, but JS messaging/telemetry is not allocation-free. Real mobile CPU, thermal, latency and hardware MIDI validation remain release gates.

The browser proof needs the server above and Chrome (`CHROME` can select its executable). It runs in a separate temporary profile, measures actual analyser output, checks held-note filter/Fullness changes and stopping/resume, and captures 320/390/1440 px layouts. It also exercises gestures, Undo, pointer cancellation/ownership and versioned file import/export. Automated signal checks do not establish musical sound quality or physical phone usability.

The current integration passes31 core groups (12 tone,7 performance,6 adaptive,5 Sauce,1 body),24 Node tests and32 actual-browser checks, plus independent scoped phone/desktop UX review. Exact-manifest auditions and45 benchmark configurations cover the updated core. These results do not establish physical-phone or musical listening acceptance. The earlier ABI4 Drive diagnostic rendered130 actual-core cases with exact manifests and two fixed-gain WAVs; it found detune-related energy movement and asymmetric-Pulse DC. Its controlled AC energy increased monotonically through Drive1/2/4/8/12, without establishing a perceptual phase-shift cause. The newer Fullness comparison covers180 cases and both real rack orders, with verified dry fingerprints and spectral-balance changes. All recordings are material for listening, not evidence that listening approval occurred.
