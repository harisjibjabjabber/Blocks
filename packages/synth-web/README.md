Current correction: [warm filter and Tone layout](../../docs/audio-references/warm-filter-performance.md). Ladder now uses scalar nonlinear feedback and raw Drive gain with the same8x reconstruction. This independent instrument loads the portable C++ core as raw WebAssembly in an AudioWorklet, with no Blocks application code or UI framework. Phase7 adds Studio generation, an8x nonlinear Ladder LP24 and repeatable Harmonics inserts alongside the existing Tone, curved envelopes, Character, drawable LFOs, Unison1–7, Width and tempo Delay. Desktop sound quality now takes priority. It remains a prototype, not a shipped VST or a replacement for Blocks production audio.

New Init selects Studio; named factories and imported files without explicit sound state retain Legacy. In Tone, the source chooser is beside Voicing; Ladder is in the existing filter Mode selector and reveals its Drive. Add Harmonics from Sauce: Soft/Asymmetric, Drive/Tone/Mix, with Dynamics and Output in Details. Dynamics reduces saturation on attacks. Mix0 retains matched filtering; power is true bypass. The [phase research/contract](../../docs/audio-references/analog-signal-path-spike.md) records measurements, processing latency and remaining listening/performance limitations.

Configured movement maxima are bounds, not guaranteed excursions: keyed background phase, random attack offsets, velocity scaling and amplitude shape affect the result. Factory patches are Velvet Current, Glass Garden and Low Tide. Preset/import/Init release voices; normal gestures do not. One completed pointer gesture creates one Undo entry. Escape/pointer cancellation restores the exact patch, and another editing pointer cannot steal the gesture; keyboard pointers remain independent. Each oscillator offers Sine, Triangle, Saw, Pulse and Square. Square fixes duty at 50%; Pulse alone follows pulse width. Independent levels can mute either oscillator without changing the other. Waveform selection changes live through a short core crossfade; no notes are rewritten. Envelope response uses curved amplitude ADSR shape to distinguish short sounds from long zero-sustain decays and slow attacks. It only attenuates requested amounts. Its stronger upper calibration now permits held depth83.92 cents at requested120 and attack allowance34.45 at requested60, with short plucks approaching full requested values. The filter ADSR is per voice, separate from amplitude, with bipolar amount in semitones around the base cutoff and an independent dry/wet mix. Its release does not extend a voice beyond the amplitude envelope. Per-note pitch settling uses a separate seeded random stream, returns toward the played pitch and scales with velocity sensitivity; it does not automate or rewrite MIDI. With drift and Hit both zero, the pitch path remains neutral; nonzero drift now intentionally follows the continuous clock. The instrument has round inline oscillator level dials, independent Mono and separate Off/Arp/Strum modes. Performance configuration is separate from the44-parameter ABI7 tone patch. Mono prioritizes physically held notes, then pedal-latched notes, with channel/key repeat counts. Switching mode/Mono panics and clears held/generated state: release and press again. Arp uses exact four-beat spans, BPM40–240, Curl±.8, straight divisions through64th and triplets through16th. The deliberate bar-seam rate reset remains. Chord changes restart immediately, with subsequent changes grouped inside a fixed non-sliding20ms window to avoid repeated restart attacks; same-sample inputs form one chord. Timing edits wait for the next bar unless a chord restart applies them first. Strum collects for20ms and spreads once over0–100ms; zero spread is immediate. Release cancels pending attacks even under pedal. The legacy performance selector remains separate modes; the new ordered note rack can cascade distinct Arp and Strum nodes. Envelope timing gestures are relative to the full plot width, with Shift providing finer desktop movement. The graph uses one linear elapsed-time axis, so a 1ms attack stays at the left edge. Its illustrative key-up follows a short hold; it is not a fixed note length. Curves use the core's `progress^(2^bend)` law; decay's vertical position sets sustain. These are UI editing maps, not changes to saved seconds or the core's automation mapping.

The visible waveform is labelled Preview when it shows ideal selected oscillator shapes, and Output (auto) when it shows actual analyser data. Display-only scaling keeps quiet playing visible and never changes the sound or acts as a level meter. Top-right Volume controls the existing output-gain parameter. Intentional Drive saturation does not itself trigger digital clipping. No end-to-end forced clipping claim is made; unit tests check threshold/channel/interval handling using known samples.

Fullness now adds stronger antialiased harmonic colour and DC-free low-band body to the dry foundation. The body is a positive additive difference between approximately180Hz and10Hz one-pole states, not a dark-filter replacement or broadband output-gain control. Fixed-gain tests at Drive12 show about+4.8dB low-band versus+1.8dB high-band change for detuned bass; overall level can rise. Core Tone colour (global Drive/Fullness, enable switches and order) remains active before the custom Sauce audio rack, including when that rack is empty. Added Drive/Fullness blocks are independent instances, up to16 ordered stages. Legacy bound-primary blocks suppress their matching base stage so colour is applied once; complete old/new paths crossfade for5ms. The processor remains generic mono audio per voice before pan. The adapter reserves 16 MiB of WASM memory, a 1024-event queue and buffers for audio blocks up to 2048 frames. Oversized blocks produce silence; queue overflow panics. The C++ render path allocates no heap memory, but JS messaging/telemetry is not allocation-free. Real mobile CPU, thermal, latency and hardware MIDI validation remain release gates.
