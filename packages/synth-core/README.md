# Portable synth core - engineering spike

Original C++17 DSP, independent of Blocks, UI frameworks, Web Audio and plugin SDKs. A C ABI is the host boundary: native hosts link the static library; the browser host compiles the same source to WebAssembly. This is not a finished VST plugin or an analogue circuit emulation.

Implemented: 16-note polyphony, independent Mono with connected-note Glide, sample-clock Curl arp and one-shot Strum, cascaded note nodes and typed free-running LFOs; per-oscillator sine/triangle/saw/pulse/square selection and independent levels; detune and pulse width; curved amplitude and filter ADSRs; legacy one-pole and opt-in resonant LP12 with dry/wet mix; continuous keyed pitch drift and per-attack settling; soft drive; per-note Pitch Drop; bounded Fullness harmonic enrichment. No unison, user-loaded wavetables, sampler, EQ, reverb or automation editor yet.

## Native build

```sh
cmake -S packages/synth-core -B build/synth -DCMAKE_BUILD_TYPE=Release
cmake --build build/synth --config Release
ctest --test-dir build/synth -C Release --output-on-failure
cmake --install build/synth --config Release --prefix /your/install/path
```

Consumers can use `add_subdirectory` or `find_package(blocks_synth CONFIG REQUIRED)` and link `Blocks::Synth`. Installed public headers are `blocks_synth.h`, `blocks_sauce.h`, `blocks_notes.h` and `blocks_modulation.h`. No runtime assets are needed. Toolchain, platform and C++ standard-library linkage still apply; there are no third-party DSP or application dependencies.

## Host contract

- Create/prepare off the audio thread; render into host-owned stereo float buffers. The core allocates no heap memory during render. Call an instance from one thread at a time; queue UI updates to the audio thread.
- Pass note, pedal and physical-unit parameter events sorted by sample offset within each block. Equal-offset events retain order. Out-of-range offsets or unsorted blocks are rejected with silence; inspect the return value.
- MIDI channel and per-key FIFO ordinals preserve ownership even after a voice is stolen: the old NoteOff consumes its original ordinal instead of releasing a replacement. Panic silences immediately. Each instance owns its voices, random state, pedal state and patch.
- ABI 7 exposes 44 stable parameter IDs with units, ranges, defaults and linear/log/discrete mappings. Waveforms at IDs 19/20 use physical values 0/1/2/3/4 for Sine/Triangle/Saw/Pulse/Square; defaults remain Saw/Pulse. Square fixes duty at 50%; Pulse alone follows pulse width. Discrete setters round to the nearest bounded integer. IDs 21/22 are independent oscillator levels, 23 filter mix, 24 filter-envelope amount, 25-31 its ADSR and curves, 32-34 settling amount/time and velocity movement, 35 envelope response, 36/37 Drive/Pitch Drop enables, 38 Sauce order (0 Drive then Fullness, 1 Fullness then Drive), 39 Fullness enable, 40 Glide enable, 41 Glide time, 42 Resonance and 43 Filter mode. Glide defaults off with time80ms. Envelope response and enables default to 1; order defaults to 0. See the header for the contract.
- Most parameters smooth with a5ms time constant. Each oscillator has five continuously smoothed waveform weights, allowing retargeting during a held note without an abrupt enum switch. ADSR and Pitch Drop settings are captured on note-on, so those changes affect new notes.
- Patch version 7 stores 44 baseline values (180 bytes). Notes, pedal, audio clock and transient envelopes are not saved. The setter accepts version 1's 18 values, version 2's 19, version 3's 21, version 4's 35, version 5's 40, or version 6's 42 without reading beyond that prefix. Old versions derive independent levels from their Mix and receive filter mix 1, filter amount 0 and disabled new movement. Versions 1/2 receive Saw/Pulse; version 1 also receives Fullness 0. Unknown versions/nonfinite values reject atomically; finite values clamp to ranges. Versions 1-4 receive envelope response 0, Drive/Pitch Drop/Fullness enables 1 and Sauce order 0, preserving their previous bypass behavior. Versions1-5 receive Glide off and time80ms. Versions1-6 receive Resonance0 and Soft filter mode0. The worklet delegates migration to this core.
- Legacy Mix (ID 1) is a compatibility shortcut: setting it sets levels to 1-Mix and Mix. Setting either level leaves the other alone and updates exported Mix to level2/(level1+level2), or 0.5 if both are zero. Version 4/5/6/7 patch levels are authoritative; an inconsistent Mix field is canonicalized. Levels each span 0-1 and can sum to 2. Hosts must use an atomic target update when setting both levels. The worklet accepts `{kind:'parameter-batch', values:[{id,value},...], frame?}`: it validates the entire batch/capacity, enqueues all at one frame in caller order, or rejects all without touching the existing queue.
- Reset clears voices and restores deterministic drift state while retaining parameters. The host owns transport and timing; the core has no wall-clock timer or Blocks tape state.

`tests/core_tests.cpp` exercises mappings, patch rejection, sample offsets/order, bounded output, sustain/overlap ownership, isolation, render allocation and block-size invariance. `tests/render_wav.cpp` produces a reproducible three-second fixture. CI compares native and WebAssembly PCM with a maximum two-unit PCM16 tolerance; exact cross-platform floating-point identity is not promised.

## Waveforms and bounded voice ownership

Sine uses an immutable2048-point table with linear interpolation. Triangle uses eight immutable Fourier tables (odd harmonic limits1/3/7/15/31/63/127/255), with continuous interpolation between safe adjacent tables. Retained partials stay below0.45 times the sample rate; tables are compiled into the binary and shared read-only between instances. There is no initialization-time harmonic synthesis or per-sample harmonic summation. Saw, pulse and fixed-duty square use the original PolyBLEP implementation. Interpolation and nonlinear drive have finite aliasing error; this is not an alias-free claim. Sine/triangle tables have zero mean. Legacy variable-width pulse retains its original DC component in the dry path for compatibility.

`tests/generate_wave_tables.py` regenerates the original mathematical tables using Python's standard library. General background is [Julius O. Smith, Wavetable Synthesis](https://mail.dsprelated.com/freebooks/sasp/Wavetable_Synthesis.html); the implementation and tables here are original and no external DSP code was copied.

Waveform changes crossfade weighted outputs with a5ms time constant and keep oscillator phase continuous. Weights normalize to one and eventually snap to exact one-hot values, allowing the original dry Saw/Pulse path to remain bit-identical after reset or a settled selection.

Voice stealing prefers quiet released voices, then pedal-held voices, then oldest held voices. A stolen voice gets a3ms snapshot fade in one of16 extra fixed slots. The replacement starts at its exact NoteOn sample while the old contribution fades. If all tail slots are occupied, the quietest remaining level x velocity x remaining-time tail is replaced, with deterministic first-slot tie breaking. This keeps memory/work bounded; it does not promise zero clicks under tail overflow. Tails do not add playable polyphony or unison and are excluded from `bs_active_voices`. Panic clears both pools immediately. Fixed per-channel/key64-bit on/off ordinals cost32KiB per instance; counter overflow resets voice/ownership state safely rather than wrapping.

## Opt-in resonant filter (ABI7)

Resonance42 spans0-1, default0. Filter mode43 selects Soft0 (the exact legacy one-pole default) or Resonant LP12=1. All versions1-6 migrate to Soft/Resonance0. Fullness and the existing filter-envelope controls are unchanged. The original linear two-integrator trapezoidal SVF implementation follows the equations in [Andrew Simper's Cytomic derivation](https://cytomic.com/files/dsp/SvfLinearTrapOptimised2.pdf); no external implementation was copied. It is not a ladder, transistor model, nonlinear feedback circuit or self-oscillator.

For effective cutoff `fc`, sample rate `fs` and resonance `r`, `g=tan(pi*fc/fs)`, `Q=sqrt(.5)*exp(log(8/sqrt(.5))*r)`, and damping `k=1/Q`. Cutoff is bounded20Hz..0.45fs after the existing envelope. The low-pass transfer at frequency `f` is `g*g / (g*g-t*t + j*k*g*t)`, where `t=tan(pi*f/fs)`. At resonance0 the new mode is a Butterworth LP12, deliberately different from Soft's LP6. Resonance reaches Q8 (approximately18dB gain at cutoff) and deliberately has no automatic loudness compensation; the existing final output saturator remains unchanged. Dry/wet mixes the actual signals before the existing colour/rack path. The browser response preview must mix complex transfer functions before taking magnitude.

Resonance uses the existing5ms control/route smoothing and is LFO-routable; mode is not. Mode changes use a10ms linear crossfade. The legacy one-pole always processes input, including while Resonant is selected, so returning to Soft restores that filter's uninterrupted state exactly after the fade. This does not promise whole-chain equality after a resonant excursion: downstream Fullness/rack histories can differ; the exact-return audio test uses neutral downstream processing. The dormant resonant states clear; entering Resonant warms them from zero under the fade. Retargeting before that fade reaches zero preserves those states. Reset starts the selected mode directly with cleared voices. Shared cached coefficients avoid repeated tangent work across voices at envelope amount0; active filter envelopes use exact per-voice tangent coefficients. There is no iterative solve, oversampling or approximate cutoff-rate stepping.

Seven focused groups in `tests/resonant_filter_tests.cpp` cover ABI6 prefix migration, atomic rejection,162 impulse complex-response measurements across8-384kHz, damped ringing, actual rendered gain, exact Soft/zero-mix bypass, mode retarget/return,16-voice rapid envelope/cutoff/resonance/LFO changes, stereo block invariance, panic and zero render allocations. The full WASM run passes78 groups in `work/synth-filter-evidence/core.log`. Response relative error is at most1.33e-12; the Q8/20Hz impulse's1.5-2s energy is7.08e-11 of its first100ms energy. This is evidence for tested modulation paths, not a general proof for arbitrary time-varying filters.

The3-second legacy PCM fixture is byte-identical to the immutable7691e66 baseline, SHA256 `713e2a56e6a5efbded6e9554e01e75326b9f1838d80dec503c606f6f388d9eee`. Native/WASM cross-runtime comparison remains a separate CI gate. `EMSDK=/path/to/emsdk node scripts/render-filter-auditions.mjs` renders four fixed-gain held-chord/pluck comparisons plus source hashes, exact patches/events and signal metrics. Clips are not individually normalized and carry no listening verdict. Paired16-voice CPU evidence and the known large live-reorder cost remain separate from musical acceptance and physical-phone testing.

## Filter envelope and per-note movement

The independent filter ADSR snapshots its attack/decay/sustain/release and three bends at NoteOn. It advances even when amount is zero, so later live modulation uses the correct note position. NoteOff/pedal release starts its own release from the current filter-envelope level; it never prolongs a voice beyond the amplitude envelope. Amount and dry/wet mix remain live smoothed controls. The cutoff is `clamp(baseCutoff * 2^(amountSemitones * envelope / 12), 20Hz, 0.45*sampleRate)`, with amount from -48 to +48 semitones. Amount 0 keeps the original cutoff path. Filter state remains warm at dry mix 0; the dry/filtered blend precedes the existing Drive. Defaults: amount 0, mix 1, attack 5ms, decay 250ms, sustain 0, release 150ms, straight curves.

Settling adds a signed, independently seeded attack offset, decaying to1% at the selected time (20ms-1s, default180ms). Its maximum is80 cents; drift depth reaches120 cents. Velocity sensitivity scales both contributions by `(1-sensitivity)+sensitivity*velocity` and snapshots per attack. Both oscillators in one voice share the pitch movement.

Background drift now follows one continuous sample clock, including idle time. Channel/key identities select distinct smooth quintic noise paths, stable phase offsets and rate multipliers0.8-1.2. NoteOn/retrigger, panic and performance-mode changes do not restart that clock. Speed changes its rate without resetting its position; prepare/reset explicitly restart it. Attack settling remains separate and freshly seeded per attack. This intentionally changes old nonzero-drift trajectories; response0 preserves manual bounds, not the obsolete restart waveform. Drift0 bypass fixtures remain the appropriate unchanged-audio comparison.

Envelope response (ID35, default1) uses curved amplitude ADSR shape rather than predicting held-note duration. Its gentle region remains unchanged, but the top is intentionally exploratory: the held drift allowance is `min(requested,29.8+.6*max(0,requested-29.8))`, or83.92 cents at120. Held attack settling uses `min(requested,8.9+.5*max(0,requested-8.9))`, or34.45 cents at60; short plucks blend toward the full requested value. The high held settling-time limit grows from60ms to120ms, never exceeding the requested time; short plucks can retain180ms. Zero Sustain with long Decay is still a long sound. These allowances precede velocity and random signed scaling, so they are not promised audible excursions. The earlier29.8/8.9 references are no longer hard ceilings.

`tests/motion_response_tests.cpp` isolates attack settling from background drift and compares adaptive/manual output pitch on the same current-core timeline. It verifies gentle-region preservation, upper-range continuity, attenuation-only bounds, stored parameter preservation, migrated v4/manual equality and sample/block invariance. Historical55.38/8.65/28.79-cent results belonged to the earlier hard-budget/restarting-drift implementation and do not describe this revision. The current isolated-Hit fixture measures early manual -33.50 cents, adaptive sustained -17.00 and adaptive short pluck -33.49. Its separate held-drift fixture measures117.18 cents raw versus81.96 adaptive, matching the83.92/120 scaling. These deterministic examples do not predict every note identity or listening experience. New before/after Mono/Poly diagnostics and listening remain separate evidence; no physical-phone or musical acceptance follows from numeric tests.

## Ordered audio rack

`blocks_sauce.h` defines a separate version1 rack configuration:328bytes with at most16 stable-ID blocks. Supported types are Drive and Fullness; duplicates use independent local amounts and enables. At most one primary block of each type binds the corresponding existing tone parameters. The public default rack is empty; the synth applies its global Drive/Fullness colour stage before the custom rack, so those tone controls remain active. A bound primary block suppresses the corresponding base stage, avoiding double processing. Independent added blocks do not suppress the base stage. Within the generic processor, an empty rack passes its input through. The private two-primary compatibility fixture reproduces the previous fixed graph exactly, including Fullness0.

`AudioRack` is a generic mono audio processor independent of notes, oscillators and the UI. Each graph owns fixed state for16 blocks. Reordering maps state by block ID rather than position. For the synth host, each graph optionally includes its own base-colour state and primary-binding suppression, so base colour and custom blocks crossfade as one complete path. Generic callers can omit that base stage. Active configuration changes crossfade for5ms; an edit during a fade replaces one pending target, applied after the current fade completes. This bounded latest-request behavior avoids discontinuities from interrupting a partially mixed graph. Local controls smooth over5ms and disabled paths stay warm. The synth still owns its final output limiting; serial Fullness stages intentionally can add level. This is a practical16-block cap, not an unlimited rack. `tests/audio_rack_tests.cpp` verifies exact default compatibility, serial duplicates, stable history, atomic rejection, pending edits, finite16-block processing and no process allocations.

The worklet accepts `{kind:'sauce',config:{version:1,blocks:[{id,type,primary,enabled,amount}]}}`, validates the whole message before writing the native328-byte struct, and acknowledges the requested configuration. Separate modulation and note-rack messages use `modulation` and `notes`; their public headers define their independent schemas. Tone patch ABI7/44 remains independent of rack topology.

## Portable modulation

Modulation is separate from the44-value tone patch: `blocks_modulation.h` defines version1 config408 bytes, up to4 sources of100 bytes, each with up to8 routes of8 bytes. The C API defaults/set/get calls validate atomically. Default source1 is Off, Sine1Hz, intensity1, with Cutoff depth.3 and Gain depth.2. Eligible targets are Gain0, Detune2, Pulse width3, Cutoff11, Drive12, Drift13, Speed14, Fullness18, oscillator levels21/22, Filter mix23, Filter amount24 and Resonance42. Unsupported/discrete/envelope targets reject instead of silently mutating unrelated controls.

Sources support Sine, Triangle, Saw, Square and smooth deterministic Random, free rate0.05-20Hz or musical divisions1/2/4/8/16/32/64 (triplets through16). Sync uses the explicit global performance tempo. Independent note-rack node tempos do not retime LFOs; legacy pending global Arp changes still follow the active tempo. Clocks advance every sample even when disabled or idle; edits/reordering preserve clocks by stable source ID. Reset restarts clocks; panic/NoteOn do not. Random paths are seeded by source identity, independently of pitch drift.

Bipolar depth * intensity * waveform offsets sum in normalized space, then a5ms per-target smoother controls effective live values. Linear targets add range * offset; logarithmic targets multiply by `exp(log(max/min)*offset)`, bounded to their descriptor ranges. Saved physical values remain untouched. Offset tails settle to an explicit zero for exact disabled baseline output. Six focused groups include actual audio, state preservation, disabled exactness, sample/block invariance and phase preservation. Host/UI acceptance is separate.

## Cascaded note rack

`blocks_notes.h` defines optional version1 config1224 bytes: up to16 ordered76-byte nodes. Arp/Strum nodes each own a bounded Performance state, and their generated events feed the next enabled generator in order. Drop nodes pass events through and supply per-note pitch recipes to the voice host. Empty or disabled racks pass input directly. Pedal enters only the first enabled generator; downstream ownership follows that generator's note events. Same-topology edits retain pending bar settings; structural changes issue one final panic and clear all internal held/queued state. `pendingMask()` exposes the waiting Arp indices. The final Mono stage is host integration, separate from each generator's mono0 config. Five focused tests cover two-generator timing, cancellation, exact passthrough, atomic validation and the16-stage allocation-free event path. Broader actual-host/UI acceptance remains separately recorded.

## Optional performance engine

Tone patches use ABI 7 with 44 parameters. Performance uses a separate version-1, 48-byte `bs_performance_config` and the additive `bs_default_performance`, `bs_set_performance`, `bs_get_performance` and `bs_performance_pending` APIs. Hosts may serialize it as an optional patch field. Seven uint32 fields (version, mode, order, division, triplet, seed, mono) occupy offsets 0-24; five floats (bpm, curl, gate, strum_ms, randomness) occupy offsets 28-44. Invalid/nonfinite settings reject atomically.

Modes are Off (0), Arp (1) and Strum (2), with an independent Mono boolean. Orders are Up, Down, As Played and seeded Random. Defaults are Off, Mono false, Up, eighth notes, no triplets, 120 BPM, Curl 0, gate 0.7, strum 35ms, randomness 0.25 and seed 0xc0ffee. Bounds are BPM 40-240, Curl -0.8 to +0.8, gate 0.1-0.95, strum 0-100ms, randomness 0-1; straight divisions are 4/8/16/32/64; triplets are supported only for 4/8/16. The core and worklet reject 32T/64T.

Mono keeps one primary voice, with bounded 3ms retirement tails for de-clicking. Physically held keys take priority over pedal-latched keys; the newest note within the selected class wins. Releasing it restores the previous eligible note. Repeated keys and MIDI channels retain independent ownership counts. In Strum+Mono, queued notes do not become restoration candidates before their own attack.

Glide (IDs40/41) applies only to connected Mono output transitions, including return to another eligible held or pedal-latched note. It interpolates log frequency over a fixed captured time, beginning at the prior primary voice's last rendered pitch, including any unfinished glide. First notes after an empty source pool and attacks after Arp gate gaps start immediately. Poly mode ignores Glide. Its enable affects new transitions; time smooths and snapshots at each transition, and a zero target bypasses exactly. Amp/filter envelopes still retrigger with the existing bounded3ms retirement tails; this is pitch legato, not envelope legato. `tests/glide_tests.cpp` measures rendered sine pitch, repeated retargeting, physical/pedal restore, exact off/zero/poly bypass, v5 migration, block invariance and render allocations.

Arp runs entirely on the core sample clock. Its four-beat phrase duration is T = sampleRate * 240 / BPM, with N = division (or division * 3/2 for triplets). Step i occurs at `T * expm1(-curl*i/N) / expm1(-curl)`; Curl 0 uses the straight fraction. Absolute phrase offsets are rounded once to a sample, avoiding accumulated interval rounding. Gate is a fraction of the actual curved interval. A new physically held key or removal from the pedal-eligible chord restarts at step one on the current sample. A pedal-latched key pressed again also restarts. Repeated same-key NoteOn ownership counts do not restart while that key remains physically held; releasing under pedal retains membership and does not restart. Pedal-up restarts only if it removes eligible notes. The restart stops the old generated gate, resets the order cursor and seeded random sequence, and applies pending settings immediately. All input events at a sample are handled before the scheduler tick, so simultaneous chord edits produce one attack chosen from the final chord. The first restart is immediate; further membership edits within20ms of that restart update the eligible note pool without resetting clock/order again. This fixed, non-sliding window avoids repeated attacks from staggered chord fingers and adds no first-note delay. Empty-to-new always restarts, even within the window. This is gesture grouping, not chord prediction. Releasing all eligible notes stops generated notes and scheduling. Random Arp selects from the held chord with replacement using the seeded generator.

Changes to active Arp settings wait until the next four-beat seam or a chord restart, whichever comes first. The getter returns requested settings; the pending API identifies an unapplied request. Restoring the active configuration before the seam cancels that pending change. Mode or Mono changes panic and clear held ownership immediately. All Off/default behavior remains the original input-to-voice route.

Strum collects new chord input for 20ms, then emits ordered notes across the selected spread once. Spread 0 emits immediately without collection latency. Random spacing uses bounded positive intervals normalized to the exact spread endpoint; random order shuffles the collected chord. New keys form a new gesture without endlessly retriggering old held notes. Releasing a key before its scheduled attack cancels that generation, even with pedal down. Pedal can sustain notes that actually sounded. Strum setting edits affect new scheduling, while already scheduled sample positions remain fixed.

The scheduler stores at most 128 unique held channel/key pairs and 128 queued Strum attacks. Excess new unique held notes are ignored until a slot becomes free; existing ownership is retained. Rendering, input handling and scheduling allocate no memory. These are bounded prototype semantics, not an external-clock synchronization implementation: there is no host tempo sync, MIDI clock, swing lane or octave expansion in this slice.

The worklet accepts `{kind:'performance', config:{...numeric fields...}}`, delegates validation to the core, and includes `performancePending` in status messages. A valid Mode/Mono change removes stale queued note/pedal input while retaining queued tone automation; an invalid config leaves the queue untouched. Stop/panic clears notes and scheduled work.

`tests/performance_tests.cpp` records internal scheduler callbacks into fixed test storage, without a production trace API. It checks exact Curl frames and endpoints across divisions/triplets, minimum interval bounds at 240 BPM, seeded orders, pending cancellation, sample-exact chord restarts, same-sample and non-sliding20ms grouping, repeated/pedal ownership, release/pedal cancellation before and after Strum publication, Mono restoration, actual audio pitch/primary voice counts, block-size invariance, panic and zero allocations. It runs in both native CTest and the WASM test script.

## Fullness: additive harmonic colour and low-band body

Fullness preserves its input and adds antialiased harmonic colour plus a separate DC-free low-band component. The whole stage is in `src/sauce.h`, after Tone and before envelope/pan. Default order is Drive then Fullness; the alternative is Fullness then Drive. Both Fullness paths remain warm, and order changes crossfade. For the input to that stage:

```
h(x) = 0.20*x*x + 0.25*x*x*x
colour = x + Fullness * DC_block(ADAA(h(x)))
body = 0.5 * (LP180(colour) - LP10(colour))
stageOutput = colour + Fullness * body
default path = Tone -> Drive -> Fullness -> envelope/pan -> master/output
other order = Tone -> Fullness -> Drive -> envelope/pan -> master/output
```

The residual input is bounded to [-1,1]; its analytic primitive extends continuously outside those bounds. The quadratic adds even colour and the cubic adds odd colour and foundation energy; the former negative linear subtraction is gone. A 10Hz DC blocker removes residual bias. Body uses one-pole alpha for 180Hz and alpha/18 for the slower average (approximately 10Hz), then adds half their difference. The difference has nonnegative real response and zero steady DC, so this linear body addition cannot cancel the dry foundation. This property does not replace actual-signal testing of the complete nonlinear rack. Fullness intentionally raises low-band energy and can raise overall level; there is no broadband gain knob, automatic normalization, pitch trim, four-pole replacement, resonance or transistor model.

The original polynomial/primitive are in `src/fullness.h`. First-order antiderivative antialiasing follows equation9 of [Parker, Zavalishin and Le Bivic, DAFx2016](https://www.dafx.de/paper-archive/2016/dafxpapers/20-DAFx-16_paper_41-PN.pdf). No external implementation was copied. ADAA reduces aliasing and adds a small delay/filtering effect to the residual; arbitrary nonlinear processing is not alias-free.

Historical fixes: the original phase/RMS-compensated wet path lost about 9–11dB on long detuned Velvet notes; a 65% wet cap still lost 7–8dB and was rejected. The subsequent `.12*x²+.20*(x³-.75*x)` pre-Tone residual removed that failure but was too subtle at high Drive. The current stronger additive body and selectable whole-stage placement supersede both. Fullness before strong Drive can still be compressed; default post-Drive placement retains a measurable low-band effect. This is original DSP, not a Moog/circuit-equivalence claim. Musical listening remains a separate gate.

Fullness0 retains the dry path with other processing equal. Every Fullness0 float-output fingerprint in the 180-case two-order comparison matched the verified earlier-core baseline. `BS_FIXTURE_FULLNESS=0` selects the separate dry golden fixture; the normal harness uses .55 to exercise current processing. Earlier nonzero audio, including former .55 fixtures, is intentionally superseded. Schema compatibility preserves physical values and explicit migration defaults, not old nonzero Fullness timbre.
