# Blocks workflow review

9 November 2026. Branch: codex/piano-roll-quality. [Draft PR](https://github.com/harisjibjabjabber/Blocks/pull/1).

## Current behavior

The handover remains the visual reference. This revision addresses the user's subsequent rejection of editor discoverability, range controls and main-screen clutter.

- Draw MIDI is visible above the empty/live roll and creates a blank four-bar layer (or eight bars when selected) in Draw mode. Playback works with no captured source and requests no MIDI permission. A selected layer has visible Edit MIDI above its roll and in the fixed transport row.
- The main screen uses one time-zoom slider, Full take, drag-to-pan and pinch zoom. On short phones the slider lives in the visible Loop popover, leaving the grid and grips above the keyboard dock. Full take reveals retained earlier notes and recorded silence. Wheel over the ruler zooms time; wheel over the piano axis adjusts note height. The editor also exposes time/pitch zoom controls.
- A dedicated bottom strip separates 48px range-grip targets from grid panning. Holding a grip at either edge for 300ms scrolls further into the retained history; Escape restores both the range and viewport. Offscreen grips have no invisible hit target. Drag across the editor ruler to set a range; drag either grip to adjust it. Grid previews and commits match. Range and note changes share ordered Undo/Redo.
- Cut range replaces the working notes in the same layer, trims crossing notes, removes notes outside the range and makes the chosen start Bar 1. Undo restores the original working notes and grid. Cutting a playing secondary layer stops it and schedules it at the shared first-loop boundary; it waits in silence until that boundary.
- The visible `4 bars ▾` control opens direct 4 / 8 / Free choices in both views, including before the first Draw. There is no nested selector. Its selected and expanded states are exposed accessibly. The choice is an action target, not a claim that the existing range already has that length. Reset loop restores an exact duration from the current start at the current tempo without deleting notes. First-layer Cut uses the selected phrase duration to establish that many bars and previews the resulting BPM. Later-layer Cut uses the established tempo. Free range preserves the manual interval and tempo. Master tempo, layer grids and Undo/Redo stay coordinated; tempo is rounded only for display. Record and automatic Capture are not silently shortened to the default.
- Live Capture and existing-layer editing are explicit separate contexts. New performance input clears a stale pending Live range, so later Capture follows the new performance. Zoom never changes capture bounds. The automatic phrase-selection algorithm is unchanged.
- First Capture applies the tempo estimate to the visible BPM, editing grid and project together; Undo restores the prior tempo. Later captures retain the established master tempo. Tempo candidates now use pinned MIT `music-tempo` BeatRoot-derived modules directly with MIDI onsets. The old fixed-lag bias (perfect 500ms attacks reporting 129 BPM) is covered by a strict 120 BPM regression. [Research, benchmarks and limitations](tempo-inference.md) explain pickups, sparse chords, competing phases, rests and half/double ambiguity. This does not change the phrase-selection algorithm or identify a downbeat.
- Record/Stop is an alternative to Capture. It retains the explicit recording interval, including leading silence, long rests and trailing silence. Capture is disabled during that explicit recording.
- BPM uses immediate minus/plus controls. Rulers show Bar labels with separate beat numbers. Vertical subdivisions follow the selected snap lattice, including triplets; finer detail appears when zooming in. Quantise directly applies the selected division at100% with Undo; advanced strength/swing preview remains available.
- Prior keyboard, multi-note editing, background layers, clipboard, capture deletion/Undo and storyboard typography remain.

## Verification

Web types, 190 JavaScript tests across 23 files and production build pass locally. The 49-check editor browser suite, 8-check loop-assistance suite and 6-check capture-tempo suite pass with zero uncaught exceptions. The new capture suite exercises a real sequence of UI keyboard notes: first Capture updates the visible/grid BPM from the estimate, Undo restores the previous tempo, first Cut derives a new tempo, and later captures preserve the master and raw note timing. The browser suite covers direct drawing from an empty project and playback, visible editor access, range/note history, exact snap positions, quantise, stale-range recovery, Record/Stop silence, same-layer cutting, full-take recovery, keyboard lifecycle and responsive layouts. It uses isolated synthetic mouse/touch input, not physical hardware or listening certification.

Product, engineering and UX departments reviewed this revision. UX rejected the initial 40px strip and the main Loop controls hidden behind the keyboard dock; both were corrected. Independent UX review subsequently passed the main/editor layouts and Loop popover at320,390 and1440 widths, and verified range auto-pan cancellation. The current visible bar selector also passed independent UX review at 320px: one action exposes all three choices and selecting a target alone does not alter the performance. The final evidence records the reviewed production bundle and the remaining physical-device/listening limits. A separate browser integration suite verifies first-Cut tempo, exact four/eight-bar reset, Undo/Redo, Free mode, inherited master tempo and left-edge touch auto-pan with Escape/second-touch cancellation. It caught and now guards against recovered offscreen grips losing their pointer listeners.

The exported build review records the final source revision and CI outcome. CI also runs native host tests; Windows has no local g++.

## Remaining scope

Takes currently remain in memory, so refreshing clears the session. Group transport, physical phone/Fold and MIDI/pedal testing, listening/latency and deployed audiovisual acceptance remain separate. Capture-prefix inference still needs its own algorithm work; this revision provides explicit recording and recovery controls without claiming that algorithm is fixed. Main and deployment remain unchanged.
