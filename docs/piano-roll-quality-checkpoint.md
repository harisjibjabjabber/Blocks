# Blocks workflow review

9 November 2026. Branch: codex/piano-roll-quality. [Draft PR](https://github.com/harisjibjabjabber/Blocks/pull/1).

## Current behavior

The handover remains the visual reference. This revision addresses the user's subsequent rejection of editor discoverability, range controls and main-screen clutter.

- Draw MIDI is visible above the empty/live roll and creates a blank four-bar layer (or eight bars when selected) in Draw mode. Playback works with no captured source and requests no MIDI permission. A selected layer has visible Edit MIDI above its roll and in the fixed transport row.
- The main screen uses one time-zoom slider, Full take, drag-to-pan and pinch zoom. On short phones the slider lives in the visible Loop popover, leaving the grid and grips above the keyboard dock. Full take reveals retained earlier notes and recorded silence. Wheel over the ruler zooms time; wheel over the piano axis adjusts note height. The editor also exposes time/pitch zoom controls.
- A dedicated bottom strip separates 48px range-grip targets from grid panning. Holding a grip at either edge for 300ms scrolls further into the retained history; Escape restores both the range and viewport. Offscreen grips have no invisible hit target. At the retained-history edge, the start grip can recover the exact earliest note even when it precedes the first snapped grid line; ordinary snapping is unchanged. Material preceding the loop is labelled Before loop, not negative bar numbers. Drag across the editor ruler to set a range; drag either grip to adjust it. Grid previews and commits match. Range and note changes share ordered Undo/Redo.
- Cut range replaces the working notes in the same layer, trims crossing notes, removes notes outside the range and makes the chosen start Bar 1. Undo restores the original working notes and grid. Cutting a playing secondary layer stops it and schedules it at the shared first-loop boundary; it waits in silence until that boundary.
- The visible `4 bars ▾` control opens direct 4 / 8 / Free choices in both views, including before the first Draw. There is no nested selector. Its selected and expanded states are exposed accessibly. The choice is an action target, not a claim that the existing range already has that length. Reset loop restores an exact duration from the current start at the current tempo without deleting notes. First-layer Cut uses the selected phrase duration to establish that many bars and previews the resulting BPM. Later-layer Cut uses the established tempo. Free range preserves the manual interval and tempo. Master tempo, layer grids and Undo/Redo stay coordinated; tempo is rounded only for display. Record and automatic Capture are not silently shortened to the default.
- Live Capture and existing-layer editing are explicit separate contexts. Each successful Capture/Record starts a fresh live tape; the captured layer keeps its own full source tape for recovery. New playing automatically shows Live, with its own first-attack origin rather than the first layer's old origin. Undo merges the prior live tape with newer events, including held-note releases, without resetting the session clock. Controller context carries across without copying old attacks. Draw does not consume uncaptured tape. Zoom never changes capture bounds. The forced last-bar fallback was removed: an existing tempo no longer cuts a continuous melody down to one bar.
- First Capture applies the tempo estimate to the visible BPM, editing grid and project together; Undo restores the prior tempo. Later captures retain the established master tempo. Tempo candidates now use pinned MIT `music-tempo` BeatRoot-derived modules directly with MIDI onsets. The old fixed-lag bias (perfect 500ms attacks reporting 129 BPM) is covered by a strict 120 BPM regression. [Research, benchmarks and limitations](tempo-inference.md) explain pickups, sparse chords, competing phases, rests and half/double ambiguity. This does not change the phrase-selection algorithm or identify a downbeat.
- Record/Stop is an alternative to Capture. It retains the explicit recording interval, including leading silence, long rests and trailing silence. Capture is disabled during that explicit recording.
- BPM uses immediate minus/plus controls. Rulers show Bar labels with separate beat numbers. Vertical subdivisions follow the selected snap lattice, including triplets; finer detail appears when zooming in. Quantise directly applies the selected division at100% with Undo; advanced strength/swing preview remains available.
- The web Synth panel offers Warm EP and Warm Pad, with per-layer ADSR dials and isolated Preview sound. Live input and the next capture follow the selected or edited sound; other existing layers remain independent. The editor preset entry fits the existing header. [Synth architecture and validation](synth-poc.md) distinguish the procedural proof of concept from future sampler libraries.
- Prior keyboard, multi-note editing, background layers, clipboard, capture deletion/Undo and storyboard typography remain.

## Verification

Web types, 210 JavaScript tests across 27 files and production build pass locally. The 49-check editor, 8-check loop-assistance, 6-check capture-tempo, 10-check layer-tape/recovery and 9-check synth browser suites verify the built app (82 checks total). The exported review records their final counts and CI result. Real browser OfflineAudioContext tests also verify distinct presets, velocity, ADSR, pedal, release and panic behavior. The new capture suite exercises a real sequence of UI keyboard notes: first Capture updates the visible/grid BPM from the estimate, Undo restores the previous tempo, first Cut derives a new tempo, and later captures preserve the master and raw note timing. The browser suite covers direct drawing from an empty project and playback, visible editor access, range/note history, exact snap positions, quantise, stale-range recovery, Record/Stop silence, same-layer cutting, full-take recovery, keyboard lifecycle and responsive layouts. It uses isolated synthetic mouse/touch input, not physical hardware or listening certification.

Product, engineering and UX departments reviewed this revision. UX rejected the initial 40px strip and the main Loop controls hidden behind the keyboard dock; both were corrected. Independent UX review subsequently passed the main/editor layouts and Loop popover at320,390 and1440 widths, and verified range auto-pan cancellation. The current visible bar selector also passed independent UX review at 320px: one action exposes all three choices and selecting a target alone does not alter the performance. The final evidence records the reviewed production bundle and the remaining physical-device/listening limits. A separate browser integration suite verifies first-Cut tempo, exact four/eight-bar reset, Undo/Redo, Free mode, inherited master tempo and left-edge touch auto-pan with Escape/second-touch cancellation. It caught and now guards against recovered offscreen grips losing their pointer listeners.

Independent UX passed the Synth panel at 320, 390 and 1440px, including pointer/touch cancellation, keyboard limits and selected-layer routing. UX blocked Escape closing the dialog during a dial cancellation; the fix now restores the dial while keeping the panel open. The exported build review records the final source revision and CI outcome. CI also runs native host tests; Windows has no local g++.

## Remaining scope

Takes currently remain in memory, so refreshing clears the session. Group transport, physical phone/Fold and MIDI/pedal testing, listening/latency and deployed audiovisual acceptance remain separate. Capture-prefix inference is still heuristic: an isolated long internal rest can still look like a new phrase, and very long uniform streams without releases retain a bounded-window fallback. These fixes remove known truncation/tape bugs without claiming to recognise user intent reliably. Native remains fixed EP; the new synth and ADSR are web-only. Sampler instruments are future work. Main and deployment remain unchanged.

Current follow-up fixes: start/end grips have separate 48px targets even for a narrow edge range; active grips stay visible when dragged beyond the plot and can be re-grabbed afterward. Capture applies the selected 4/8-bar length as a soft start preference near a played attack, while retaining full source tape.


## Editor zoom and immediate layer editing follow-up

The user-facing snap default is 1/4. The editor exposes Time and Keys sliders directly above the roll; the time ruler and keyboard axis retain wheel/pinch gestures. Selecting a snap division reveals its lattice at readable spacing, including triplets; selecting a coarser division restores enough context to show its lines. Manual zoom remains free. White-key rows are lighter than black-key rows in both themes.

Note edits with unchanged timing replace future events in the current audio cycle while preserving its epoch and other layers. Deleted/changed pitches release promptly. Events already passed by the playhead play on its next pass; the scheduler keeps its existing 25ms audio lookahead. Duration/origin/stretch changes still use the seam path. Per-block Volume is available in layer actions, with a dedicated source gain and a short ramp; it does not rewrite velocities or change another layer. Web only.

The main view exposes Cut range directly and uses compact minus/plus/Fit controls. Captured clips cannot pan or zoom beyond their available extent; after Cut, that extent is the trimmed loop and the Before loop prefix disappears. The editor retains free navigation and source recovery. Undo restores the previous trimmed-view state with notes and bounds. Takes remain in memory.

Validation: 213 JavaScript tests, types and build passed; focused headless checks cover quarter default, fine triplet autozoom, pitch slider, 320/390/1440 controls, layer volume access and main cut/fit limits. The editor regression suite is rerun after updating its main zoom gesture to the new controls. Physical-device listening remains unverified.


Zoom/seek follow-up: editor sliders now live inside one Zoom popover, dismissed by outside press or Escape. Both range grips remain reachable at viewport edges when zoomed, with separate hit targets; dragging an offscreen edge starts from its visible edge. Main-view panning and drag auto-scroll use the same bounded viewport. The cut clip extent is stored independently of the editable range, so moving the first seeker cannot shrink the available history. Focused browser regression verifies zoom, re-grabbing the first seeker and Fit restoring the original cut extent.
