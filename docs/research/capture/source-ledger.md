# Source ledger: Blocks Capture research

All sources were accessed on **8 Nov 2026**. The evidence classes are:
- **DOC-ABL**: documented Ableton behaviour, i.e. what Ableton's own manual, help pages or release notes say a user can observe.
- **CODE**: public code I opened and read.
- **PAPER**: a paper or patent.
- **HYP**: our inference, not stated by the source.
- **OURS**: our design.

I have no access to Ableton's implementation and make no claims about how it works internally. Every "why" about Ableton below is labelled HYP.

HYP labelled inferences from A1-A4 (not stated by Ableton): (H1) its "phrase" detection uses gaps, since a longer gap is needed when stopped. (H2) It prefers loop lengths of 1, 2, 4 or 8 bars. (H3) With the transport running, it picks a bar-aligned range against the existing tempo. (H4) Latency compensation is applied at capture time. We adopt these only as design ideas of our own, and they are tested on our fixtures.

## E. What we took vs. what's ours (summary)

- Taken as **documented observable behaviour** (A1-A4): the two-mode split (an empty stopped Set infers tempo; an existing or running Set uses the existing tempo), the 80-160 BPM band, the advice to end on the next downbeat, keeping notes outside the chosen loop, loop lengths of 1/2/4/8 bars in the one-note case, the first note being the loop start for loops of ≤8 bars (Live 11.1), choosing the iteration with new material when overdubbing, a bounded event buffer, and latency compensation at loop jumps.
- Taken as **ideas from public code or papers**: a bounded ring (C1), bar-count retro capture with an early margin (C2), IOI clustering with integer-ratio scoring (C4, C6, R2), LBDM boundary strength (R1), meter levels (R3), and MIR metrics (C5).
- **Ours**: the layered journey model, the three-way distinction between alignment, quantise and tempo, the sounding model with CC64/CC66 latch and optional voice activity, bounded candidates with explicit abstention, bar-range candidates against the project clock, cycle-locked capture for free-time loops, the LCM/length policy, seam and tail handling, controller correction ops, and the fixture set and harness.
